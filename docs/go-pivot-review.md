## §24 — Kill / Pivot Triggers

For each signal, record whether it is **Present** in the pilot data and the action taken (or planned). The team should not continue building solely because the app already exists.

| Signal | Plan action | Observed? | Action taken / planned | Owner |
|--------|-------------|-----------|------------------------|-------|
| Owners refuse to list without upfront payment/guarantees | Rework trust/value proposition before more engineering | ☐ Yes / ☐ No / ☐ Unclear | | |
| Contractors prefer existing brokers despite equivalent supply | Investigate broker-as-partner model | ☐ Yes / ☐ No / ☐ Unclear | | |
| Bookings occur but repeat usage is weak | Stop feature expansion; diagnose value failure | ☐ Yes / ☐ No / ☐ Unclear | | |
| Founder coordination time stays extremely high | Automate only the repeated bottleneck or reconsider model | ☐ Yes / ☐ No / ☐ Unclear | | |
| Unit economics remain negative without subsidy | Change pricing/GTM before scaling | ☐ Yes / ☐ No / ☐ Unclear | | |
| Supply exists but demand does not | Stop supply acquisition and focus on demand | ☐ Yes / ☐ No / ☐ Unclear | | |
| Demand exists but supply is unreliable | Focus on supply quality/availability | ☐ Yes / ☐ No / ☐ Unclear | | |
